# Saving ~75 min in the dual-seed + HOCT veto pipeline (same output, less HOCT deadline risk)

https://www.kaggle.com/competitions/biohub-cell-tracking-during-development/discussion/741242  
author Hammad Farooq, posted 2026-09-14 04:24:30.653000, votes 1, comments 0, last comment None

<p>Hi everyone,</p>
<p>I've been working with the public <strong>dual-seed UNet-transformer + DeepCenter + HOCT veto</strong> pipeline (credit to the original authors and dataset owners, links below). While reading through a full run's logs I found a simple runtime saving that doesn't change the submission, and I think it matters more on the hidden test set than on the 4 public example videos.</p>
<h2>What I noticed</h2>
<p>The notebook spends a lot of time before it writes the final submission:</p>
<table>
<thead>
<tr>
<th>Stage</th>
<th>Time (2× T4)</th>
</tr>
</thead>
<tbody>
<tr>
<td>Validator prediction on 8 held-out train videos</td>
<td>~16 min</td>
</tr>
<tr>
<td>Scoring the base post-process config</td>
<td>~7 min</td>
</tr>
<tr>
<td>Sweep of 7 post-process candidates</td>
<td>~51 min</td>
</tr>
<tr>
<td><strong>Total before the final write</strong></td>
<td><strong>~75 min</strong></td>
</tr>
</tbody>
</table>
<p>The sweep only uses <strong>train</strong> videos, which are the same on every rerun. So it picks the same winner every time. In my runs that was:</p>
<pre><code>SELECTED: tight55  overrides={'MOTION_RELINK_TIGHT_UM': 5.5}
  base     proxy=0.9490 adj=0.9260 divJ=0.2308
  selected proxy=0.9511 adj=0.9280 divJ=0.2308
</code></pre>
<h2>The change</h2>
<ol>
<li>Set the selected value directly in the config cell:</li>
</ol>
<pre><code>os.environ["BIOHUB_MOTION_RELINK_TIGHT_UM"] = "5.5"
</code></pre>
<ol>
<li>Remove the validator prediction, the base scoring and the sweep cells.</li>
<li>Remove the first <code>write_test_submission("base")</code> call. That file gets overwritten later anyway. Write <code>submission.csv</code> <strong>once</strong>, with the HOCT veto armed.</li>
</ol>
<p>Detection, linking, ILP, post-processing and HOCT mode stay exactly the same.</p>
<h2>Why it matters for the private LB</h2>
<p>The HOCT veto has a wall-clock budget (<code>BIOHUB_HOCT_DEADLINE_H = 10</code>) and skips any video it predicts won't finish in time. On the public example set HOCT took ~18 min total, and the largest video (~70k nodes) alone took ~12 min. The hidden test set is about the size of the training set, so the veto can realistically hit the deadline. If it does, the remaining videos are written <strong>without</strong> the veto.</p>
<p>Freeing ~75 min gives HOCT that much more room, so fewer hidden-test videos should be skipped.</p>
<h2>Caveats</h2>
<ul>
<li>Please diff <code>submission.csv</code> before and after on your own run. Small GPU nondeterminism can change a few rows.</li>
<li>The local proxy uses only 8 videos, so treat small proxy differences with caution.</li>
</ul>
<h2>Open questions</h2>
<ul>
<li>Has anyone measured HOCT <strong>mode 1 vs mode 2</strong> on a held-out split? The notebook's validator never scores the veto itself.</li>
<li>Division Jaccard on the local validator is low (3 TP / 1 FP / 9 FN). Has anyone found post-processing that improves divisions without hurting edge Jaccard?</li>
</ul>

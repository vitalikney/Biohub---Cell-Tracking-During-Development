## 5. Таблица чтения K2 и двойника (кратко)

**Обозначения**
- d1 = K2 − #35 (0.954); d2 = двойник − #34 (0.953).
- d1 «чистый», если в `ledger.md` верхняя граница L(K2) ≤ 8.0 ч, то есть COMPLETE увиден до ~08:01Z.

**Правила** (первое подходящее выигрывает):
1. **K2 = ERROR.** K1 в следующий слот [OK]. F2 = двойник по f2, иначе exp52.
2. **Двойник − K2 ≥ +0.002.** R2 открывается снова, F1 = двойник. F2 = K2, если d1 ≥ −0.001 [OK]; иначе K1 [OK]; иначе exp52.
3. **d1 ≥ −0.001.** lowrefine остаётся, F1 = K2. F2 = двойник, если он ≥ 0.953; при 0.952 — двойник с порогом 0.952 [OK], без OK — exp52. При ≤ 0.951 или ошибке F2 = exp52.
4. **d1 ≤ −0.002 и d1 чистый.** lowrefine уходит из стека F1, нужен K1 [OK]. F2 = двойник, если он ≥ 0.953, иначе exp52. Если K1 нет: F1 = двойник [OK], без OK — #34.
5. **d1 ≤ −0.002, но d1 не чистый.** Это конфаунд времени, решает d2:
   - d2 ≤ −0.002 — как в п. 4;
   - иначе F1 = K2, F2 = двойник или exp52, и пользователю поднимается триггер времени (сначала сравнить L(двойника) с L(K2)).

**Никогда:** K1 при d1 = −0.001; exp56, пока есть допустимый файл семейства x138, не являющийся копией; два файла с одинаковыми компонентами.

## Что может и чего не может твой Mac

Может: всё, что считается на CPU из кэшей друга A: анализ графов, кластеризация на сохранённой контрольной точке,
стадия делений и финальные фильтры, официальная метрика. Это и есть твоя работа, GPU для неё не нужен.

отправляй на лидерборд.

**Важно:** общий раздел Onboarding в `TEAM.md` написан для GPU-машин. Его требования CUDA, `ilpy`/`pyscipopt` и
скачивания 82–88 ГБ данных к тебе не относятся. Для B31 источник истины — этот файл и
`experiments/local_friend_c_b31_cluster/README.md`.

## Установка

1. `git clone`, `git checkout -b friend-c`. Python 3.11 arm64 (miniforge или venv). Установи только CPU-зависимости
   точной командой из `experiments/local_friend_c_b31_cluster/README.md`. PyTorch, CUDA, `ilpy` и `pyscipopt` не нужны.
   Kaggle API нужен только чтобы скачать пакет ниже (`pip install kaggle`, токен из настроек Kaggle).
2. Пакет друга A (он публикует его 20 сентября и пишет слаг и `<tag>` в чат команды; если ещё нет, спроси Виталия).
   Внутри: `cache/<tag>/raw/<stem>.geff` (сырые графы публичного стека до пост-обработки, с скором каждого узла),
   `dc/<stem>.npz` (скор DeepCenter на КАЖДОМ сыром узле по `node_id`, это вето стадии делений, посчитано на GPU),
   `ckpt/<stem>.npz` (контрольная точка после закрытия разрывов) для всех 199 видео, плюс `train/<stem>/…` с
   разметкой `.geff` без zarr-картинок. Распакуй и выставь `export BIOHUB_LOCAL_CACHE=<путь>/cache`,
   `export BIOHUB_DATA_DIR=<путь>/train`.
3. Контроль: открой из корня `friend-c-b31-cluster.ipynb`, укажи распакованные `BIOHUB_LOCAL_CACHE` и
   `BIOHUB_DATA_DIR`, выполни preflight и долгую ячейку. Радиус `0` на всех 199 видео обязан воспроизвести цифры друга A
   из `experiments/local_friend_a_b20_divnet/results/b20_final.md`: score 0.9120275, adj_edge 0.9023109, деления
   24/96/127. Проверка встроена и сама остановит sweep при несовпадении. Готовые видео сохраняются; для мягкой остановки
   создай напечатанный ноутбуком файл `STOP`, затем удали его и перезапусти ячейку для продолжения.

Почему теперь не `tools/public_local.py --stage pp`: кэш `dc` содержит оценки только существующих сырых узлов, а полная
стадия gap-closing спрашивает DeepCenter и для новых синтетических точек. Без кадров это нельзя честно воспроизвести.
Поэтому рабочий CPU-эксперимент начинает с `ckpt` после gap-closing, кластеризует узлы до делений и финальных фильтров,
а `dc` применяет к кандидатам делений по сохранённому `node_id`. Это зафиксированная граница B31, а не скрытая смена
рецепта.

## Задача B31: кластеризация дублирующих узлов, срок 23 сентября

Механизм. Метрика штрафует лишние узлы: множитель `1 − 0.1·(N_pred − N_est)/N_est`, а публичный стек на пороге 0.965
даёт на 3–4% узлов больше оценки, это около 0.003 скора. Слепая обрезка по скору и NMS проверены и теряют полноту
(узлы, которые они режут, стоят внутри треков, см. B25 в `CONTEXT.md` §10a). Гипотеза hengck23 (гроссмейстер Kaggle):
часть лишних узлов это ДУБЛИ одного ядра (два пика детектора на одной клетке), их надо не резать, а сливать:
внутри кадра жадно по убыванию скора узла подавлять соседей в радиусе r и оставлять лучший. Дубли не сидят внутри
треков поодиночке, поэтому провал B25 здесь не повторяется, а число узлов падает.

Шаги, каждый с отчётом в чат:
1. **Сколько дублей вообще есть.** На сырых графах всех 199 видео посчитай для каждого узла расстояние до ближайшего
   соседа в том же кадре (в микронах, воксели 1.625 по z и 0.40625 по xy, шкала в `CONTEXT.md`). Гистограмма и доля
   узлов с соседом ближе 1, 2, 3 мкм. Сравни с разметкой: доля GT-ядер с соседом ближе 3 мкм (настоящие ядра
   ближе ~4 мкм почти не бывают). Если пиков ближе 2 мкм меньше 1%, рычага нет, и ты честно так и пишешь.
2. **Кластеризация.** Радиус r из {0.5, 1.0, 1.5, 2.0} мкм, жадно по убыванию `peak_prob`, оставить лучший наблюдаемый
   узел, остальные стянуть в него вместе с рёбрами. Синтетические gap-узлы не кластеризовать. Операция выполняется на
   `ckpt` после gap-closing и до делений/финального tail. Для каждого r на всех 199 видео: отношение N_pred к контролю,
   TP рёбер, adj_edge, деления, score. Всё это делает `friend-c-b31-cluster.ipynb`; таблица сохраняется рядом с
   контролем.
3. **Ворота:** score ≥ контроль + 0.005 на всех 199 видео при adj_edge не хуже чем на 0.001. Если прошло, Виталий
   собирает ядро и отправляет одну пробу. Если лучшее r даёт +0.002…+0.005, тоже напиши, с числом узлов: такое идёт
   как кандидат во второй финал без пробы. Если ничего, B31 закрыт.

# CellTracker — постоянный контекст для агентов

Этот файл помогает продолжать работу без истории переписки. Здесь хранятся цель проекта, устройство данных, правила проверки и устойчивые решения. Метрики запусков, выбранные пороги, тайминги, номера эпох и сравнения гипотез относятся к отчётам экспериментов и сюда не переносятся.

Контекст сверён с проектом 2026-09-06. Следуй текущему заданию пользователя: описанная ниже стратегия сама по себе не поручает запускать обучение или все эксперименты при каждом открытии проекта.

## Цель

Построить воспроизводимое решение соревнования [Biohub — Cell Tracking During Development](https://www.kaggle.com/competitions/biohub-cell-tracking-during-development): по 3D-видео развития эмбриона данио-рерио находить центры клеток, связывать их между кадрами и восстанавливать деления и родословные.

Результат — ориентированный граф положений клеток во времени и корректный `submission.csv`. Качество определяется официальной метрикой на независимых данных. Полные маски сегментации не являются требуемым выходом; использовать их как промежуточное представление можно, если это оправдано измерениями.

Validation использует физический Euclidean NMS и оптимальное one-to-one сопоставление в микронах с учётом downsampling. Во время обучения ячейка показывает progress-bar, loss, VRAM и обновляемый SVG-график; после validation добавляется holdout recall. История и `last.pt` сохраняются до validation, лучший проверенный checkpoint — как `best.pt`; checkpoint хранит и восстанавливает Torch/NumPy/Python/CUDA RNG и проверяет совместимость split/config. Исправленный baseline пишет по умолчанию в `outputs/detector_44b6_to_6bba_v2`, старые detector-checkpoint намеренно несовместимы. CUDA smoke-run, короткий training с неполной группой gradient accumulation и полный проход validation одного 100-кадрового видео проверены; многоэпоховое обучение и полная validation намеренно требуют явного включения в конфигурации и пока не запускались. Linker, сборка графа, официальная graph-validation и submission в основном notebook ещё не реализованы. `biohub_cell_tracking_profiled.ipynb` остаётся историческим снимком раннего GPU-профилирования, а не версией текущего pipeline.

## Что известно о данных

При первоначальном аудите 2026-09-05 обнаружено:

- 199 обучающих роликов: 71 с префиксом `44b6` и 128 с префиксом `6bba`; организатор подтвердил два исходных эмбриона в train.
- 4 доступных локально тестовых ролика. Их ID встречаются и в train; совпадение ID само по себе не доказывает идентичность пикселей и не создаёт независимый holdout.
- Форма каждого проверенного видео — `(T, Z, Y, X) = (100, 64, 256, 256)`, тип `uint16`.
- Пространственный масштаб `(Z, Y, X)` — `(1.625, 0.40625, 0.40625)` мкм/воксель.
- 133 318 размеченных положений клеток и 128 883 ребра. Это положения во времени, а не число уникальных клеток.
- 151 размеченное деление, посчитанное по родительским узлам с двумя потомками: 26 и 125 в двух группах. Не путай число делений с числом исходящих из них рёбер.
- Все проверенные GT-рёбра связывали соседние кадры; максимум один родитель и два потомка, слияний не обнаружено.
- Число размеченных положений составляет примерно 2,8% от суммы оценочного полного числа положений клеток в метаданных. Это приблизительная характеристика разреженности, не точный class prior.

Это результаты аудита конкретной версии данных, а не константы загрузчика. Обнаруживай наборы, формы, оси, масштаб и метаданные из файлов. Имена и число скрытых test-наборов могут отличаться. В проверенных image attrs отдельного `embryo_id` не было; группировку по префиксу нужно явно документировать, а при появлении достоверных метаданных использовать их.

## Разреженная разметка и координаты

- GT покрывает только часть настоящих клеток. Отсутствие аннотации не является надёжной отрицательной меткой клетки или связи.
- Обучение должно явно учитывать известные и неизвестные области/связи. Слабый отрицательный вес, masked loss и псевдометки — отдельные проверяемые решения. Простое исключение всех отрицательных примеров без защиты от вырожденного предсказания также не является готовым решением.
- Recall на размеченных центрах и ошибка локализации полезны как диагностика. Долю найденных точек без GT-совпадения нельзя выдавать за полный detection false-positive rate.
- Расстояния для сопоставления, NMS и ограничения кандидатов считай с учётом физического масштаба. Шаг по Z здесь в четыре раза больше шага по X/Y.
- Отслеживай преобразования после downsampling, crop, padding и аугментаций. На выходе нужны координаты исходного массива; нельзя повторно применять масштаб или оставлять координаты уменьшенного изображения.
- Если используется временное окно, согласованно преобразуй изображения, центры и векторы движения. Произвольное обращение времени меняет деление на слияние и требует отдельного обоснования.

## Официальная метрика — обязательный источник истины

Используй закреплённую реализацию организаторов: [metrics.md](C:/Projects/CellTracker/vendor/kaggle-cell-tracking-competition/metrics.md), [metrics.py](C:/Projects/CellTracker/vendor/kaggle-cell-tracking-competition/src/tracking_cellmot/metrics.py), [evaluate.py](C:/Projects/CellTracker/vendor/kaggle-cell-tracking-competition/scripts/evaluate.py). Перед финальным сравнением с Kaggle проверь актуальные изменения организаторов: метрика делений уже исправлялась.

Текущая формула: `score = adjusted_edge_jaccard + 0.1 * division_jaccard`. Сопоставление узлов проводится по кадрам с физическим порогом 7 мкм. Это порог сопоставления с GT, а не готовый радиус поиска связей между кадрами.

Поправка для одного видео: `J_adj = max(0, J * (1 - 0.1 * (N_pred - N_est) / N_est))`. `N_est` берётся из `estimated_number_of_nodes` в GT-метаданных и включает неразмеченные клетки. Не подставляй вместо него число размеченных GT-узлов. Значение выше 1 само по себе не означает ошибку; не добавляй произвольное ограничение сверху.

В закреплённом коде `evaluate_datasets()` возвращает результат с **непоправленным** edge Jaccard. Для конкурсного результата нужен путь `evaluate()` → `per_sample_metrics()` с корректным `N_est` → `summarise()`, либо эквивалентный официальный путь из `scripts/evaluate.py`. Поправленные edge-значения усредняются с весами `TP + FP + FN`; division Jaccard считается из суммарных TP/FP/FN.

- Проверяй покрытие всех ожидаемых validation-наборов. Официальный скрипт работает по пересечению имён и может пропускать неудачные наборы; это нельзя молча выдавать за полный результат.
- Показывай отсутствующие оценки числа клеток, ошибки чтения и NaN. Не заменяй их удобными значениями и не скрывай исключение сложных видео.
- Различай пустое предсказание и сбой обработки: пустое предсказание не повод убрать видео из оценки.
- Выбирай итоговые модели и параметры по полной метрике, сохраняя её компоненты. Loss, pairwise accuracy и `accuracy * recall` не заменяют её.
- При изменении обёртки оценки проверь совпадение с официальным кодом, включая локальные деления, пустые графы и повторный расчёт. Evaluator может записывать matching-атрибуты в переданный граф.

## Валидация и защита от утечки

Основная схема разработки — обучение на одном эмбрионе и проверка на другом, затем обратное направление. Сохраняй manifest состава групп. Случайное разделение кадров или роликов одного эмбриона подходит для отладки, но не доказывает перенос на другой эмбрион.

- Не допускай одного эмбриона по обе стороны независимой проверки, включая пересекающиеся фрагменты.
- Проверяй происхождение готовых весов. Веса, обученные на отложенном эмбрионе, не дают честной независимой оценки на нём.
- Псевдометки и обучаемые статистики должны соблюдать границы fold. Validation GT используется для оценки и выбора параметров, не для построения входов или предсказаний.
- Инференс получает изображения и разрешённые метаданные. GT-центры нельзя подставлять вместо детекций; такой режим допустим только как явно обозначенная диагностическая проверка.
- Диагностика связывания на GT-центрах искусственно упрощает задачу из-за отсутствия неразмеченных соседей. Не выдавай её за итоговое качество.
- Отчитывайся отдельно по обоим эмбрионам и по агрегированной официальной метрике. Два эмбриона ограничивают надёжность оценки обобщения.
- Доступные test-примеры и их совпадающие train-ID не заменяют независимую валидацию. Скрытый тест обрабатывай тем же алгоритмом без использования train-разметки по имени файла.

## Рабочее направление разработки

Начальная архитектурная опора — модель организаторов: `TemporalUNet3D` для центров и признаков клеток, `SimpleNodeTransformer` для связей. Сначала нужен воспроизводимый полный baseline и разбор ошибок: пропущенные центры, неверные связи, неверные деления.

Дальнейшие гипотезы, а не уже доказанные улучшения:

1. Более корректное обучение детектора по неполной разметке.
2. Дополнительное предсказание смещения назад к родителю, как в [Linajea](https://github.com/funkelab/linajea). При делении обе дочери могут указывать на одного родителя.
3. Локальный граф кандидатов по физическому расстоянию, движению и признакам; согласованный выбор связей с ограничениями на родителей и потомков.
4. Детекция делений по нескольким кадрам и более частая выборка редких размеченных делений внутри обучающего fold.

Выбирай следующий шаг по измеренному источнику ошибок или затрат. Сравнивай изменения на одинаковой проверке; ускорение не должно незаметно менять координаты, граф или методику оценки. Улучшение на одном отладочном batch не является улучшением решения соревнования.

## Контракт графа и submission

- Узел задаёт `node_id`, `t`, `z`, `y`, `x`; ID уникален внутри dataset. Разные dataset могут иметь одинаковые node ID — не объединяй их графы.
- Ребро ссылается на существующие узлы одного dataset и направлено от `t` к `t+1`. Не создавай циклы, self-loops и дубли рёбер.
- У узла максимум один родитель и два потомка. Начало/конец трека допустимы, в том числе при выходе из кадра; не навязывай всем клеткам продолжение.
- CSV имеет столбцы `id,dataset,row_type,node_id,t,z,y,x,source_id,target_id`.
- Для `node` заполняются ID узла, время и целочисленные координаты исходных вокселей; `source_id` и `target_id` равны `-1`.
- Для `edge` заполняются `source_id`, `target_id`; `node_id,t,z,y,x` равны `-1`.
- `id` — последовательный индекс строк. `dataset` совпадает с фактическим именем тестовой папки без `.zarr`. Все тестовые наборы должны быть обработаны.
- Проверяй границы координат и кадров, ссылки, охват наборов и обратное чтение CSV. Результат оценки сохранённого и повторно прочитанного графа должен совпадать с исходным при одинаковом представлении координат.
- Финальная цель — Kaggle Notebook с офлайн-инференсом и `submission.csv`; зависимости и веса должны быть доступны без интернета. Перед подготовкой submission сверяй актуальные правила и время исполнения, оценивая полный скрытый объём, а не только четыре локальных примера.
